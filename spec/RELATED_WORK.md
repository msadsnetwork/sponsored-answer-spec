## Conclusion (honest)
- **Ads inside AI conversations are NOT an empty space.** AdCP Sponsored Intelligence already standardizes sponsored responses and brand-agent handoffs, at the media-buy and agent-protocol level. We must not claim we invented "sponsored answers".
- **What we did not find** in any of the sources above: an **OpenRTB 2.6 bid-request extension** that describes a chat/agent ad slot impression by impression, so ordinary DSPs can bid on a single conversational moment in real time. That means intent and decision stage, language including script and Roman Urdu or code-mixed text, consent, no-PII turn context, allowed answer formats, and enforceable disclosure rules, plus a matching bid response and events. **[UNVERIFIED that nobody has one]**: we did not search every OpenRTB community extension or vendor-private `ext`. Before publishing, check the OpenRTB `extensions/community_extensions` folder and ask the IAB Tech Lab OpenRTB working group.
- **What our spec adds:**
  1. A bidstream path (OpenRTB 2.6, existing DSPs, `at=1` first price) instead of an MCP-only media buy.
  2. Formats the publisher or agent owner renders from a short, supplied creative, so small chatbots don't need an LLM ad-generation platform.
  3. Language and script signals (`ur` + `Latn` = Roman Urdu, `code_mixed`).
  4. Disclosure rules a machine can check (label before the content, sponsor visible, validator).
  5. Hooks for IVT reason codes (D1–D6).
  6. A payout-statement hook (Idea 3).
  7. Backward compatibility with our live `msads-agent/0.1`.
- **How it fits with others:** a bridge, not a rival. We reuse Agentic Audiences for embeddings, and an AdCP SI "sponsored response" product could be fulfilled through this OpenRTB extension (a mapping is planned for v0.2).
